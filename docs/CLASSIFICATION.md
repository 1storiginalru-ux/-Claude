# Смысловая разметка жалоб и исправление прежних меток

## Что исправлено

Прежние локальные правила считали любое упоминание стойкости, подделки, упаковки,
маркировки или доставки жалобой. Затем высокая оценка и любая метка принудительно
выставляли скрытый негатив. Поэтому даже «аромат, стойкость» или «быстрая доставка»
попадали в негатив. Проблема была шире одного слова «нет».

Версия `rules-2.0` ищет фразы о проблеме, а не название темы. Для Маркета отдельно
используются `description.advantages`, `description.disadvantages`,
`description.comment`; для WB — `pros`, `cons`, `text`. Поля берутся только если
их объединённый текст совпадает с текущим текстом обращения: устаревший JSON
не должен менять смысл новой редакции.

| Пример при оценке 5 | Результат правил |
|---|---|
| Достоинства: «аромат, стойкость» | Без жалобы |
| Недостатки: «нет», «не обнаружено», «не нашла» | Без жалобы |
| Недостатки: «нет и быть не может, не первый раз заказываю» | Без жалобы |
| «Вроде не подделка, норм!» | Без жалобы |
| «Однозначно оригинал», «Нет сомнений в оригинальности» | Без жалобы |
| «Цена, качество, быстрая доставка. Спасибо за подарок» | Без жалобы |
| «Хорошая упаковка», «коробка не повреждена» | Без жалобы |
| Недостатки: «стойкость» | Предварительная жалоба на стойкость |
| «Нет стойкости», «аромат исчезает через час» | Жалоба на стойкость |
| «Это не подделка, но упаковка помята» | Жалоба на упаковку |
| «Нет, это подделка!» | Сомнение в оригинальности, Human Only |
| «Нет запаха», «распылитель не работает», «нет крышки» | Реальная проблема сохраняется |

Слово «нет» не удаляется из всех отзывов. Отрицание конкретной проблемы подавляет
только соответствующую фразу: «коробка не повреждена, но флакон протёк» сохраняет
жалобу на дефект. Соседние предложения и поля не склеиваются для поиска проблемы.

Оценка 4–5 не превращает название темы в скрытый негатив. Для этой метки нужна
реальная жалоба; оценка 1–3 остаётся основанием для проверки даже при положительном
тексте. У вопросов нет метки скрытого негатива отзыва.

Это ограниченные локальные правила, а не гарантированное понимание всех русских
формулировок. Уверенность остаётся 0, черновик не создаётся; решение сотрудника
сохраняет приоритет. Спорные, ироничные и сложные формулировки требуют проверки.
На экране результат rules обозначается как возможный скрытый негатив.

## Подключённый AI

В инструкцию модели добавлены примеры положительных упоминаний, отрицания проблем
и отсутствия недостатков. В контекст передаются отдельные поля `review_sections`.
Классифицируется текущий отзыв покупателя; ответы продавца не являются его жалобой.
Метка hidden_negative больше не принуждается из одного факта наличия signals:
положительный результат AI с темой LONG остаётся положительным. Настоящая
отрицательная тональность при высокой оценке по-прежнему считается скрытым негативом.
Версия инструкции — `classification-2.0`. Реальный AI-ключ при проверках не использовался.

Если покупатель перенёс то же слово из достоинств в недостатки, смысл меняется,
даже если объединённый текст остался тем же. Анализ запускается заново. Существующее
решение сотрудника сохраняется с аудитом, но помечается устаревшим до повторной
проверки. Изменения лайков, числа комментариев и прочей метаинформации этого не делают.

## Пересчёт прежних записей

Установщик сервера и локальный запуск после миграций автоматически выполняют
`refresh_rules --apply`. Обновление включает и предыдущую доработку ручных решений,
очереди контроля, правил и расследований. Отдельная установка двух версий не нужна.

Пересчитываются только существующие записи `Analysis.provider=rules` старой версии
без ручного решения. До и после сохраняются в аудите `analysis.rules_refresh`.
Повторный запуск не переписывает уже обновлённые записи. Ручные решения, внешний
AI-анализ и демо-разметка не перезаписываются. Сетевые запросы не выполняются.

Сохраняются исходный текст/JSON, сообщения, опубликованные ответы, статусы обращений,
привязки, продажи, очереди, курсоры и паузы API. Старые расследования не удаляются
и не закрываются: ответственный проверяет их доказательства и результат вручную.

Для просмотра количества и предполагаемых изменений без записи:

```bash
voice-manage refresh_rules --account ЯМ_1
```

Для сохранения с аудитом (после штатного обновления обычно уже нечего менять):

```bash
voice-manage refresh_rules --account ЯМ_1 --apply
```

Без `--account` проверяются все кабинеты. В локальной установке вместо
`voice-manage` используется `.venv/bin/python manage.py`.
