# Сопоставление артикулов

`ProductID` — ваш внутренний ID физического товара. Один и тот же ID можно
использовать для товара в нескольких кабинетах. Отдельная строка импорта
связывает этот товар с одним артикулом одного кабинета.

| Площадка | SKU | External Product ID |
|---|---|---|
| Wildberries | Числовой артикул WB, `productDetails.nmId` | Тот же `nmId` |
| Яндекс Маркет | Артикул продавца, `offerId` | Внешний ID из вашего каталога; при его отсутствии повторите `offerId` |

Артикул продавца WB (`supplierArticle`) сохраняется в исходных данных отзыва
и виден в сведениях о товаре, но для сопоставления больше не используется.
`imtId` и штрихкод также не являются артикулом WB.

## Обычный импорт

1. Откройте **Product Mapping**.
2. Выберите компанию, которой принадлежит кабинет из файла.
3. Выберите **Product Mapping**, затем CSV или XLSX.
4. Нажмите **Проверить и импортировать**.

Заголовки:

```text
ProductID, Product Name, Brand, Volume, Concentration, Platform, Account, Legal Entity, SKU, External Product ID
```

`Account` и `Legal Entity` должны точно совпадать с настройками приложения.
Если кабинеты принадлежат разным компаниям, импортируйте их файлы отдельно,
каждый раз выбирая компанию соответствующего кабинета. Совпадение юридического
лица само по себе не объединяет две компании приложения.

Один файл — до 5 МБ и 5000 строк, Excel без формул. Повторный импорт тех же
сопоставлений не создаёт дублей. Конфликт не перезаписывает прежний товар:
весь текущий файл откатывается. Ранее успешно импортированные файлы остаются.
Уже загруженные отзывы без товара привязываются к сопоставлению этого кабинета.
Дата отзыва здесь не ограничена неделей: ограничение 7 суток относится к запросам
маркетплейсов, а импорт каталога работает локально.

## Если каждый кабинет находится в отдельном столбце

Для таблицы с заголовками `ID`, `Брэнд`, `Товар`, `Тип`, `Объем`
и отдельными столбцами артикулов есть команда подготовки. Она не меняет базу
и не отправляет запросов в маркетплейсы. Названия столбцов и кабинетов
вы задаёте явно.

Пример для столбцов `ВБ1`/`ЯМ1`, кабинетов `ВБ_1`/`ЯМ_1`
и юридического лица `АМ`:

```bash
.venv/bin/python manage.py prepare_mapping "$HOME/Downloads/Сопоставление артикулов.xlsx" --wb 'ВБ1=ВБ_1' --ym 'ЯМ1=ЯМ_1' --legal-entity 'АМ'
```

Измените путь, если файл лежит в другой папке. Результат находится в новой
папке `.local/mapping-import/…`; команда напечатает точные пути. Откройте
эту папку в Finder и загрузите полученные XLSX через обычный импорт.

Команда принимает исходный файл до 5 МБ, до 100000 строк и до 30 МБ
в распакованном Excel. В каждом выходном файле будет не более 5000 строк.
Обрабатываются только явно выбранные столбцы, пустые артикулы пропускаются.
ID, артикулы и описания записываются как текст; ведущие нули в текстовых
артикулах Маркета сохраняются. `Объем` допускает до 240 символов, чтобы
не обрезать состав наборов. Повторы артикулов и противоречивые описания
одного ID отклоняются. Незаполненные сведения не придумываются.

Новый запуск создаёт отдельную папку, готовые файлы не перезаписываются.
Исходная таблица и результаты остаются локально: каталог `.local/` исключён
из Git. Не добавляйте реальные выгрузки товаров в репозиторий.

## Обновление с версии, использовавшей артикулы продавца WB

Остановите приложение через Ctrl+C. В его папке выполните:

```bash
.venv/bin/python manage.py backup_db
git pull --ff-only
bash start.sh
```

`start.sh` автоматически применит миграцию `0005`. Она не обращается к WB:

- восстанавливает `nmId` из сохранённого JSON отзывов;
- переводит прежние сопоставления по их числовому `External Product ID`
  либо по однозначному `nmId` из сохранённых отзывов;
- переносит ключи связанных дневных продаж, сохраняя количества и даты;
- сохраняет сообщения, статусы, AI-анализ, очередь ответов и сроки пауз;
- записывает прежние и новые ключи в аудит.

Если для старого отзыва `nmId` неизвестен, прежний артикул сохраняется
в аудите, поле SKU остаётся пустым до получения достоверного `nmId`.
Существующая связь с товаром в этом случае сохраняется. Старые сопоставления
без достоверного `nmId` не используются для новых отзывов: их нужно исправить
или заменить после проверки. Демо-данные и Маркет не переводятся.

При конфликте двух сопоставлений одного `nmId` или двух дневных строк продаж
миграция останавливается с пояснением и откатывает свои изменения. Данные
не складываются и не перезаписываются автоматически. После исправления
конфликта повторите запуск. Обратная миграция ключей не поддерживается;
для полного возврата используйте резервную копию и прежнюю версию программы.
