# История для последних 100 выкупов

Один физический товар объединяется по внутреннему ProductID (`Product.code`).
Сопоставления связывают его с артикулами нескольких кабинетов и площадок.
Цель — последние **100 выкупленных единиц суммарно**, а не по 100 в каждом
кабинете. Возвраты считаются отдельно и не вычитаются из этого знаменателя.

## Что загружается автоматически

- WB: продажи и возвраты из оперативного API статистики. Нужны включённые
  продажи кабинета и ключ с правами «Статистика».
- WB, Яндекс Маркет и Ozon: отзывы за период, соответствующий окну продаж.
  Сохраняются исходные поля и доступные ссылки на фото/видео.
- Яндекс Маркет: продажи через API заказов и статистики после отдельного включения; [инструкция и неподтверждённые даты](YANDEX_SALES.md).
- Продажи Ozon — CSV/XLSX. Отсутствие данных не заменяется нулями.

После обновления у реальных включённых кабинетов по умолчанию включена настройка
**Догружать историю до 100 выкупов**. Демо не опрашивается. Нужны сопоставления
артикулов; без них неизвестно, какие товары требуется заполнить.

## Как расширяется период

Текущий опрос остаётся отдельным: последние 7 суток. После его первого полного
цикла загрузка продаж расширяется на 14 → 30 → 60 → 90 дней, пока по каждому
сопоставленному товару не набрано общее окно 100 единиц и не подтверждена полнота
продаж за него. На каждой глубине загружается отчёт всего кабинета; отдельного
запроса на каждый артикул нет. Существующие события используются повторно,
повтор страницы не увеличивает счётчик. Для дневного импорта включается целиком
граничный день, поэтому общее число может немного превышать 100.

90 дней — предел автоматического обхода. WB описывает доступность оперативного
отчёта за 90 дней от создания заказа: это не гарантия наличия всех операций
старых заказов. Если выкупов меньше 100, показывается фактическое число и
недостаточная выборка. Более старая локальная история сохраняется и может
участвовать в окне, если за него подтверждена полнота всех источников.

Отзывы догружаются до начала того же окна, максимум на 90 дней назад.
У WB проверяются три списка: без ответа, с ответом и отдельный архив
`/api/v1/feedbacks/archive`. Архив обходится по убыванию дат; у этого метода
нет фильтра `dateFrom/dateTo`, граница проверяется локально. Полнота отзывов
подтверждается только после завершения всех трёх списков. Обход вопросов
при этом не объявляется исторически полным. У Маркета используются
`dateTimeFrom/dateTimeTo` и продолжение `page_token`.

## Лимиты, публикации и разметка

В `voice-poll` выполняется по одной странице за проход. У истории свои позиции,
паузы и блокировки, но общий API-бюджет с текущими запросами. Сохранённые 429 и
заголовки ограничения соблюдаются; ручная команда не сбрасывает паузу. Для
истории периодически выделяется очередь запросов, чтобы текущий опрос не
занимал весь лимит. Исходящие ответы имеют приоритет перед историей отзывов.
На базовом токене статистики WB начальная загрузка может занять много часов.

Старые отзывы не открывают заново закрытые обращения и не публикуют ответы.
История не вызывает платный AI: применяется предварительная локальная разметка
с уверенностью 0. Ручные решения и существующий анализ сохраняются; изменённый
текст требует новой проверки. Правила по словам не становятся подтверждённым
негативом. Для достоверного показателя нужна проверка оператором или достаточная
уверенность AI, а также полные продажи и отзывы за общий период.

## Где смотреть

В **карточке товара** показаны число выкупов, длительность окна, даты и причины
неполноты. В **Интеграциях** у кабинета показаны состояния истории продаж и
отзывов, завершённая глубина, продолжение страницы и следующая попытка.
Процент остаётся прочерком при неполных данных или неразобранных отзывах.
Серия подтверждённых жалоб может требовать контроля раньше набора 100 выкупов.

На сервере прочитать состояние без сетевого запроса:

```bash
voice-manage history_status --account ВБ_1
voice-manage sales_status --account ВБ_1
```

Для диагностики — одна страница с соблюдением всех пауз:

```bash
voice-manage sync_history --account ВБ_1 --kind sales
voice-manage sync_history --account ВБ_1 --kind reviews
```

Отдельную службу для истории запускать не нужно. Миграция `0008` добавляет
настройку и отдельные состояния; текущие курсоры, API-паузы, продажи, отзывы,
сопоставления, ручные решения, расследования и опубликованные ответы не сбрасывает.

Проверка контрактов использует сохранённые модели публичного
`wildberries-sdk@0.1.174` и спецификации API Маркета. Контрактные тесты не
заменяют сверку доступности архива и чисел на реальном кабинете продавца.
