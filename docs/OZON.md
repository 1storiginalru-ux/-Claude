# Ozon и новые юридические лица

## Структура

| Юрлицо | Кабинет | Площадка | Переменная ключа |
|---|---|---|---|
| ЕС | ВБ_2 | Wildberries | VOC_WB_2_TOKEN |
| ЕС | ЯМ_2 | Яндекс Маркет | VOC_YM_2_TOKEN |
| ЕС | Ozon_2 | Ozon | VOC_OZON_2_TOKEN |
| ОП | ВБ_3 | Wildberries | VOC_WB_3_TOKEN |
| ОП | ЯМ_3 | Яндекс Маркет | VOC_YM_3_TOKEN |
| Velato | ВБ_Velato | Wildberries | VOC_WB_VELATO_TOKEN |
| Velato | ЯМ_Velato | Яндекс Маркет | VOC_YM_VELATO_TOKEN |
| Velato | Ozon_Velato | Ozon | VOC_OZON_VELATO_TOKEN |

ЕС и ОП записываются кириллицей. Существующие АМ, ВБ_1 и ЯМ_1 не меняются.
Создание повторяемое: имеющиеся кабинеты, ключевые переменные, включение и
параметры не перезаписываются. При конфликте принадлежности или площадки
команда откатывается целиком. Новые кабинеты отключены; ключей в базе и Git нет.
У новых компаний нет унаследованного Tone of Voice и подтверждённых знаний:
их следует заполнить отдельно. Суперпользователь видит новые компании;
доступ остальных сотрудников назначается в администрировании через Membership.

## Обновление сервера

В SSH-окне сервера:

```bash
systemctl stop voice-web voice-worker voice-poll &&
voice-manage backup_db &&
cd /opt/voice &&
git pull --ff-only &&
bash deploy/install.sh --provision-accounts &&
systemctl enable --now voice-web voice-worker voice-poll
```

Миграция `0009` добавляет Ozon и Client-Id, сохраняя рабочие данные и паузы.
Юрлица создаются только при явном `--provision-accounts`, а не при миграциях:
свежая база остаётся пустой для переноса с Mac. Отдельная проверка структуры:

```bash
voice-manage provision_accounts
```

Для создания без повторной установки добавьте `--apply`.

## Подключение ключей

Для Ozon нужны **Client-Id** и **API Key** одного кабинета Seller.
Операции отзывов и вопросов в доступных описаниях требуют **Premium Plus**;
фактические права и доступность проверяются в конкретном кабинете. HTTP 403
показывает ошибку доступа, а не пустой список отзывов. Клиент и ключ каждого
кабинета вводятся отдельно.

На сервере сохраните ключ скрытым вводом:

```bash
voice-set-key VOC_OZON_2_TOKEN
```

Публичный числовой Client-Id задайте в **Интеграции → Ozon_2 → Настроить кабинет**
или командой (замените 123456 своим Client-Id):

```bash
voice-manage configure_account --account Ozon_2 --client-id 123456 --enable
systemctl restart voice-web voice-worker voice-poll
```

Прочитать настройку без сетевых запросов или проверить один запрос отзывов:

```bash
voice-manage diagnose_ozon --account Ozon_2
voice-manage diagnose_ozon --account Ozon_2 --probe
```

Для проверки вопросов добавьте `--kind question`. Проверка не импортирует
обращения и не меняет позицию загрузки, но соблюдает общий API-бюджет.

Для Ozon_Velato используйте его отдельный ключ `VOC_OZON_VELATO_TOKEN` и Client-Id.
Ключи из чата не попадают на VPS автоматически; ввод в терминале сохраняет их
непосредственно в `/etc/voice/voice.env`. Команды не печатают значения ключей.

Другие площадки подключаются аналогично. Примеры:

```bash
voice-set-key VOC_WB_2_TOKEN
voice-manage configure_account --account ВБ_2 --enable
voice-set-key VOC_YM_2_TOKEN
voice-manage configure_account --account ЯМ_2 --business-id 123456 --enable
systemctl restart voice-web voice-worker voice-poll
```

Число в `--business-id` замените Business ID нужного бизнеса Маркета.
`configure_account` проверяет наличие ключа и соответствие идентификатора
площадке; команда сама не делает запросов API и не подтверждает валидность ключа.
Автоматические продажи WB и Маркета отдельно включаются в карточке кабинета с нужными правами. Для WB — «Статистика»; для Маркета — чтение заказов и статистики. [Инструкция](YANDEX_SALES.md). Не подключайте один магазин повторно под разными именами.

## Возможности интеграции

- Текущий опрос отзывов и вопросов за последние 7 суток, включая обработанные.
  Для отзывов используется `/v2/review/list` с `filters.published_from/to`,
  для вопросов — `/v1/question/list` с `filter.date_from/to`. Границы дополнительно
  проверяются локально. Позиции страниц сохраняются после полной обработки.
- `/v2/review/info` догружает ссылки на фотографии и видео: список отзывов их
  не содержит. Полный полученный JSON сохраняется и доступен для скачивания.
  API не возвращает отдельные достоинства/недостатки в используемом списке:
  система не придумывает эти поля.
- История комментариев к отзывам и ответов на вопросы, авторы, исходные статусы
  модерации, продолжение страниц после пауз, повтор без дубликатов.
- Ответ оператора через `/v1/review/comment/create` или
  `/v1/question/answer/create`. Текст — 2–3000 символов.
  Создание комментария само не переводит отзыв на Ozon в «обработанные».
  Локальные статусы также не меняют внешний статус автоматически.
- Sent означает приём запроса, Confirmed — подтверждённую публикацию.
  Комментарий Ozon или другого участника не принимается за ответ компании.
  Для вопросов принадлежность подтверждается сохранённым ID нашего ответа;
  одного имени автора или совпадения текста недостаточно. При неопределённом
  результате без ID нужна ручная сверка в Seller, повтор не выполняется автоматически.
- Отклонение собственного ответа модерацией видно как ошибка отправки;
  потребуется исправить текст. Ожидающий модерации ответ не становится Confirmed.
- Сохраняемый общий бюджет Ozon для опроса, истории, отправки и сверки.
  HTTP 429 и Retry-After переживают перезапуск; это отдельный бюджет от WB.
- Разметка, решения оператора, Human Only и контроль товара работают через
  существующие механизмы. История отзывов за окно продаж догружается до 90 дней,
  когда по сопоставленным товарам известен период продаж.

## Сопоставления и ограничения

Для Ozon оба поля **SKU** и **External Product ID** должны содержать числовой
**Ozon SKU**, который возвращается в отзыве, а не offer_id/артикул продавца.
Один ProductID объединяет физически одинаковый товар между компаниями и
площадками. Импорт CSV/XLSX поддерживает Platform=Ozon. В `prepare_mapping`
доступно `--ozon СТОЛБЕЦ=КАБИНЕТ`.

Продажи Ozon через API, чаты, удаление/редактирование ответов и массовое изменение
внешних статусов в эту доработку не входят. Для продаж Ozon используется
существующий импорт дневных данных; неизвестные продажи не считаются нулевыми.
Ссылки медиа могут истекать; файлы не архивируются локально. Публикация ответов
и доступность истории зависят от действующей версии API, прав и модерации Ozon.

Контракты сверены с публичными пакетами `@seller-sdk/ozon@0.4.0` (snapshot
октября 2026, v2 отзывов) и `daytona-ozon-seller-api@2.2.17` (v1 комментариев и
вопросов). Официальная точка документации: https://docs.ozon.ru/api/seller/.
В среде разработки официальный сайт был недоступен; запросы реального продавца
и публикация проверяются после установки и ввода ключей на вашем сервере.
