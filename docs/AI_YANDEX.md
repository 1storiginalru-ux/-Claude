# Яндекс AI Studio: очередь, знания и пилот

Обновление не подключает провайдера и не ставит историю на платный анализ.
Автоматическая обработка новых отзывов выключена по умолчанию, существующие
решения операторов, кабинеты, продажи и лимиты маркетплейсов сохраняются.

## Установка на существующий сервер

При первом обновлении службы voice-ai ещё нет. Остановите прежние три службы,
а новую — только если она установлена:

```bash
systemctl stop voice-web voice-worker voice-poll
if systemctl cat voice-ai.service >/dev/null 2>&1; then systemctl stop voice-ai; fi
voice-manage backup_db
cd /opt/voice
git pull --ff-only
bash deploy/install.sh
systemctl enable --now voice-web voice-worker voice-poll voice-ai
systemctl is-active voice-web voice-worker voice-poll voice-ai
```

Установщик добавляет unit, но сам не включает AI worker. Для последующих
обновлений останавливайте все четыре службы перед миграциями. На Mac
`bash start.sh` запускает отдельный AI worker вместе с прежними процессами.

## Аккаунт и модель

1. В AI Studio создайте платёжный аккаунт и каталог, доступный вашей организации.
2. Создайте сервисный аккаунт с правами вызова текстовых моделей в выбранном
   каталоге (роль `ai.languageModels.user` или актуальная роль из консоли).
3. Создайте API-ключ с правами выполнения выбранной модели. Сохраните его
   непосредственно на сервере, а не в карточке компании или Git:

```bash
voice-set-key VOC_YANDEX_AI_KEY
```

4. Получите доступные URI моделей. Здесь `YOUR_FOLDER_ID` заменяется на публичный
   ID вашего каталога:

```bash
voice-manage diagnose_ai --folder-id YOUR_FOLDER_ID --list-models
```

Список приходит из `GET https://llm.api.cloud.yandex.net/v1/models`, с заголовками
`Authorization: Api-Key …` и `OpenAI-Project: …`. Название из тарифной таблицы
не обязательно совпадает с ID API. **Не подставляйте придуманный URI Flash**:
выберите точный `gpt://…` из ответа, соответствующий Alice AI LLM Flash,
и по возможности закрепите версию для испытания.

5. Настройте только АМ. В существующей базе это две компании: «ВБ 1» и «ЯМ_1».
   Выбор по юрлицу применяет настройки к обеим; ЕС, ОП и Velato не изменяются:

```bash
voice-manage configure_ai --legal-entity АМ --folder-id YOUR_FOLDER_ID --model YOUR_EXACT_MODEL_URI --token-limit 1000000
voice-manage configure_ai --legal-entity АМ --folder-id YOUR_FOLDER_ID --model YOUR_EXACT_MODEL_URI --token-limit 1000000 --apply
systemctl restart voice-web voice-poll voice-ai
voice-manage diagnose_ai --company 'ВБ 1' --probe
voice-manage diagnose_ai --company ЯМ_1 --probe
```

`--probe` — один маленький платный синтетический запрос, без реальных отзывов
и изменений базы. Он не входит в локальный лимит очереди. Не запускайте его
в цикле. Проверка соединения не доказывает качество классификации.

## Профиль и знания

В разделе Tone of Voice заполните обе записи АМ. Профиль для первого испытания:

> Пишем по-русски, на Вы. Спокойно, уважительно, кратко: обычно 1–3 предложения.
> Отвечаем на конкретный отзыв. Без рекламных приглашений, чрезмерных извинений,
> канцелярита и фразы «Ваше мнение очень важно для нас». Не повторяем весь отзыв.
> Не объясняем причины проблемы без подтверждённых фактов. Не обещаем возврат,
> компенсацию, сроки и свойства товара, которых нет в знаниях. При недостатке
> данных задаём один необходимый вопрос. Не добавляем подпись отдела или имя,
> пока они не согласованы компанией. Эмодзи по умолчанию не используем.

Это пример для пустого профиля, а не замена согласованному стилю компании.
Если компания утвердила обязательную подпись, умеренные эмодзи или другую длину,
используйте её документ. Заполнитель `{{имя_сотрудника}}` нужно заменить перед
публикацией; сервис блокирует незаполненные шаблоны также перед фактической отправкой.

Это стартовый стиль, а не факты о компании. Общие подтверждённые правила сервиса
хранятся в поле «Подтверждённые знания». Не заполняйте его предположениями.

Стиль и знания можно загрузить двумя отдельными файлами в той же форме.
Форматы TXT, Markdown, DOCX, PDF с текстом. Лимит стиля 16000 символов,
знаний 24000; некорректный второй файл не сохраняет частично первый.
Для загрузки через терминал используйте явный список кабинетов:

```bash
voice-manage import_ai_profile --legal-entity АМ --account ВБ_1 --account ЯМ_1 --voice /PATH/voice.md --knowledge /PATH/knowledge.md
```

По умолчанию это просмотр. `--apply` сохраняет профиль с приватной копией
прежних полей в `/var/lib/voice/backups` и аудитом в БД. Модель, ключи, лимиты,
автоанализ и очередь не меняются. Если несколько кабинетов относятся к одной
компании, перечислите их все: профиль общий для компании. Повторный импорт
тех же файлов идемпотентен.

Абзацы знаний могут начинаться с `[ALL]`, `[WB]`, `[YM]` или `[OZON]`.
Явно помеченные сведения другой площадки не попадают в запрос. Абзац без
маркера считается общим, поэтому не объединяйте разные процедуры в одном
немаркированном фрагменте. Площадка, её название и публичность обращения
передаются модели из Voice; она не должна переспрашивать место покупки.

Факты о конкретных товарах добавляются через «Добавить подтверждённый факт»:
компания, ProductID, название, текст, источник, подтверждение и активность.
Черновые и выключенные записи не используются. Источник — документ или
ответственный, у которого проверен факт. ProductID оставляется пустым только
для общих сведений. Общий профиль не является местом для каталога всех товаров.

Первый поиск локальный: отбор по компании, ProductID и словам запроса, до четырёх
целых фрагментов общей длиной до 6000 символов. Поле знаний старого формата
разбивается на абзацы; абзацы длиннее 3000 символов пропускаются — такие сведения
перенесите в отдельные записи. Это RAG без embeddings и внешней векторной базы.
Семантический поиск можно добавить после проверки качества на реальном корпусе.

Классификатор получает текст, оценку, отдельные поля отзыва и карточку товара;
он не получает tone of voice или ответы продавца. Генератор получает классификацию,
профиль, выбранные факты и последние шесть сообщений как непроверенную историю
общения. История не считается доказательством. Внешнему API не отправляется
полный JSON маркетплейса или вся база. Знания и история хранятся в Voice, а
вызовы API не обучают модель автоматически.

## Партия из 30 отзывов

Сначала просмотрите выборку, затем поставьте её в очередь:

```bash
voice-manage enqueue_ai --legal-entity АМ --limit 30
voice-manage enqueue_ai --legal-entity АМ --limit 30 --apply
voice-manage ai_status --company 'ВБ 1'
voice-manage ai_status --company ЯМ_1
```

Для одного товара добавьте `--product 3102`. Подтверждённые человеком отзывы
партия пропускает. Ручное решение «Требует проверки» сохраняет приоритет:
AI-анализ не превращает его автоматически в подтверждённую разметку.
В выборку желательно включить положительные отзывы, «Недостатки: нет», явный
и скрытый негатив, жалобы на стойкость/оригинальность и неоднозначные случаи.
Команда выбирает последние отзывы; разнообразие нужно проверить вручную.

Результаты видны в «Очередь AI» и карточках обращений. Повторное нажатие кнопки
использует готовый результат той же версии. Изменение отзыва, профиля или знаний
создаёт новую версию. Явный платный пересчёт без изменений доступен через
`enqueue_ai … --force --apply`. Существующие оценки операторов не переписываются.

Перед массовым включением проверьте пропуски жалоб, ложный негатив, долю правок
черновиков, соблюдение Human Only, выдуманные факты, usage и задержки. Качество
не проверено одними модульными тестами: нужен реальный вызов модели.

После приёмки автоматический анализ включается отдельным вызовом
`configure_ai … --auto on --apply`, с теми же параметрами каталога, модели и
осмысленным лимитом. Опрашиваемые отзывы не анализируются повторно без изменений.
Историческая загрузка остаётся на локальных правилах, её платный анализ выбирается
отдельной ограниченной партией. Само обновление или включение AI не ставит архив
на обработку. Ни одна AI-задача не публикует ответ: публикацию подтверждает оператор.

## Надёжность и расход

Два этапа: классификация, затем черновик только при достаточной уверенности и
разрешённой категории. LONG/AUTH (стойкость и оригинальность), RETURN, MARK, P0
и серьёзный DEFECT — Human Only. При конфликте сильного локального сигнала и
ответа модели нужна проверка человека. Уверенность модели сама по себе не доказывает
правильность результата.

Очередь хранится в PostgreSQL/SQLite. HTTP выполняется вне транзакций. Lease и
проверка версии не дают старому worker перезаписать изменившийся отзыв. Успешная
классификация сохраняется отдельно: при сбое черновика повторяется только второй
этап. Временные ошибки повторяются до пяти попыток с задержками и Retry-After;
ошибки ключей/прав требуют исправления. Ошибка не превращается в «нет негатива».

Перед каждым вызовом резервируется консервативное число токенов. Если API
сообщает достоверный usage, резерв заменяется фактическим расходом. После
таймаута, прерывания worker или ответа без usage резерв остаётся в месячном
лимите как неизвестный расход. Одновременные worker не используют один остаток
лимита дважды. Отказы авторизации/валидации и 429 освобождают резерв.

Лимит задаётся **на компанию и календарный месяц МСК**, не на юрлицо целиком
и не в рублях. Например, две записи АМ имеют два отдельных лимита. Это локальная
защита, а не точный счёт провайдера и не ограничение его платёжного аккаунта.
После достижения лимита задача ждёт следующего месяца; для немедленного
продолжения увеличьте лимит и повторно поставьте выбранные задачи.

Пока реализован синхронный Chat API Яндекса, вызываемый из фоновой очереди.
Асинхронный тариф Яндекса, автоматический резервный провайдер, денежный лимит,
семантический поиск и сравнение двух моделей в одном экране пока не реализованы.
Провайдер переключается явно, профили и знания остаются в Voice.

При смене ключа перезапустите web/poll/ai, чтобы они получили новое окружение.
Ошибки проверяются через `ai_status` и `journalctl -u voice-ai -n 40 --no-pager`.
Отдельный worker не содержит модель и не требует GPU на сервере Voice.

## Проверенный контракт

Источник: официальный `yandex-cloud/yandex-cloud-ml-sdk`, текущий пакет
Yandex AI Studio SDK. Пути `_chat/base_function.py`, `_chat/completions/model.py`,
`_auth.py`, а также записанный тест `test_structured_output_simple_json.yaml`:
`POST /v1/chat/completions`, полный `gpt://` URI, JSON response_format,
max_tokens, usage.prompt_tokens/completion_tokens и finish_reason.
Документация: https://aistudio.yandex.ru/docs/ai-studio/ .

Автоматические проверки используют контролируемые HTTP-ответы без реальных
ключей. Доступ с Beget, доступность Alice Flash в вашем каталоге, действующие
права/тариф и качество реальных ответов проверяются после подключения аккаунта.
