## Исправление ограничения частоты Wildberries

- Полный набор: **77 тестов прошли**. Добавлены 14 проверок HTTP 429, заголовков лимита, общего бюджета, продолжения загрузки и очереди ответов.
- Проверено сохранение паузы 720 секунд и чтение этой паузы отдельным процессом: новый процесс не отправляет запрос до разрешённого времени.
- После HTTP 429 загрузка продолжает сохранённую страницу с прежней временной границей. Прерванная страница может быть получена повторно без дублей сообщений.
- Проверено подтверждение публикаций перед загрузкой архива и сохранение ответов в Queued при лимите. Локальное ожидание бюджета не расходует попытки отправки.
- SIGTERM завершает polling и освобождает блокировку синхронизации; пауза API и позиция загрузки остаются в БД.
- Применена миграция `0003`: созданы служебные таблицы ограничения частоты и позиции загрузки, в журнал добавлено время повторной попытки. Исходные таблицы обращений и кабинетов не пересоздаются.
- Проверки выполнены на контролируемых ответах HTTP и отдельных локальных процессах. Реальная синхронизация WB остаётся для проверки на Mac пользователя.

## Диагностика повторного HTTP 429

- `diagnose_wb` показывает локальный этап и количество обращений без сети. Флаг `--probe` разрешает один GET с `take=1`, соблюдая сохранённую паузу и блокировку синхронизации.
- Шесть дополнительных тестов проверяют отсутствие запросов по умолчанию и во время паузы, выбор кабинета, неизменность курсора и обращений, вывод заголовков лимита и скрытие ключа даже при его отражении в ошибке сервера.
- Полный набор: **83 теста прошли**; `check`, проверка миграций и `git diff --check` прошли. Реальная причина ответов WB на Mac пока не установлена; для неё нужен результат диагностики пользователя.

## Конкурентная работа с SQLite

- Исправлен конфликт чтения и последующей записи в транзакциях: SQLite использует `IMMEDIATE`, WAL и ожидание записи до 30 секунд. Это настройки подключения; таблицы и данные не пересоздаются.
- Временные SQLite BUSY/LOCKED в polling и worker не завершают процессы. Другие ошибки базы продолжают явно сообщаться. Начатая отправка при сбое локальной записи не повторяется автоматически.
- Полный набор: **91 тест прошёл**. Новые проверки используют отдельную файловую базу и реальные конкурентные соединения: читатель не блокирует commit, две транзакции чтения с записью завершаются без потери обновлений. Проверены восстановление фоновых циклов и отсутствие повторной отправки при конфликте записи после успешного ответа API.
- Отдельная проверка на временной базе с миграциями: четыре процесса одновременно загрузили и проанализировали 1000 отзывов, выполнили 300 изменений компании, 1000 циклов чтения и обработали исходящую очередь. Ошибок блокировки нет, ответ отправлен один раз через заглушку адаптера. Реальные API не вызывались.
- На существующей облачной базе подтверждён WAL и сохранение 12 демо-обращений; включённых кабинетов нет. Проверка выполнена в Linux, повтор на Mac пользователя остаётся необходимым.

Поля новых данных первоначально пусты, заполнение выполняет polling. Сохранение исходящей очереди также покрыто тестами публикации и подтверждения.

## Синхронизация только за последние 7 суток

- Полный набор: **135 тестов прошли**. Добавлены 15 проверок точной границы 168 часов, часовых поясов, фильтров каждого API, пагинации, прерванного старого архива, фоновой дозагрузки и диагностики.
- В запросах WB явно передаются `dateFrom`/`dateTo`. Старая позиция полного архива заменяется недельной; актуальная позиция страницы и фиксированная верхняя граница сохраняются при паузе. Нижняя граница двигается вперёд, истёкшие записи не импортируются даже после долгого ответа API.
- Маркет получает явный недельный фильтр для отзывов; для вопросов дополнительно проверяется время создания, поскольку API принимает только даты. Старые, будущие и недатированные строки не импортируются. Такие же ограничения действуют при фоновой дозагрузке известных обращений по ID.
- Старые локальные записи не удаляются, остаются в Inbox и JSON-выгрузке; в недельные счётчики «Интеграций» не входят. Для них отключены фоновые запросы полных данных и истории. Проверка публикации уже отправленного оператором ответа сохраняется и подтверждается отдельным тестом для старого отзыва.
- Проверки `check`, отсутствия новых миграций и `git diff --check` прошли. Значения API-ключей и реальные кабинеты при проверке не использовались.
