# Отдельный сервер Ubuntu 24.04

Для начала: 2 vCPU, 4 ГБ RAM, 40–60 ГБ SSD/NVMe. Приложение работает
под пользователем `voice` с отдельной группой `voice-app`, PostgreSQL использует локальный Unix-сокет и peer
аутентификацию этого пользователя. Пароль PostgreSQL в этой схеме не нужен.
Роль `voice` не получает права суперпользователя, создания ролей или баз.
Локальный запуск на Mac и SQLite сохраняются без изменений.

В Ubuntu/Debian группа `voice` уже может существовать как системная группа
голосовой почты. Установщик сохраняет её и использует отдельную `voice-app`.
Если пользователь `voice` уже создан предыдущей версией, его UID и членство
в группах не изменяются; службы явно запускаются с группой `voice-app`.

## Подготовка сервера

Выполняйте в SSH-сеансе на новом выделенном сервере как root:

```bash
apt-get update
apt-get install -y git python3-venv python3-dev build-essential libpq-dev postgresql postgresql-contrib nginx certbot python3-certbot-nginx
git clone https://github.com/1storiginalru-ux/-Claude.git /opt/voice
bash /opt/voice/deploy/install.sh
```

Если `/opt/voice` уже существует, не удаляйте каталог: сначала проверьте
его содержимое. Для существующей установки порядок обновления описан ниже.
Установщик рассчитан на выделенный сервер со свободным портом 8000,
кодом в `/opt/voice` и локальной базой `voice`. Чужие службы не останавливает.

Установщик создаст приватный файл `/etc/voice/voice.env` с новым случайным
секретом Django. Повторный запуск сохраняет этот файл, данные и логины.
Состояние, статические файлы и резервные копии — в `/var/lib/voice`.
Новая база проходит миграции, демо и стандартный пользователь не создаются.

Создаются службы:

| Служба | Назначение | После установки |
|---|---|---|
| `voice-web` | Gunicorn, два процесса, по два потока | Запущена и включена в автозапуск |
| `voice-worker` | Очередь публикации ответов | Остановлена |
| `voice-poll` | Получение отзывов и вопросов | Остановлена |
| `voice-backup.timer` | Ежедневная локальная резервная копия | Включена |

`voice-web` слушает **только `127.0.0.1:8000`**. Подключение извне к порту
8000 не требуется. Настройки Nginx на этом этапе не изменяются.
Процессы работают без root, код доступен им только для чтения через
ограничения systemd, запись разрешена в `/var/lib/voice`.

## Первая проверка без домена

Откройте отдельное окно Terminal **на Mac**. Подставьте свой IP и путь к ключу:

```bash
ssh -i "$HOME/.ssh/voice_beget" -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -N -L 18000:127.0.0.1:8000 root@SERVER_IP
```

Оставьте это окно открытым. В браузере этого Mac откройте
`http://127.0.0.1:18000/`. Трафик между компьютером и сервером идёт внутри
SSH; запросы не проходят через открытый HTTP в интернете. Это способ первой
проверки владельцем, для сотрудников дальше настраивается домен с HTTPS
или корпоративный VPN. Существующее серверное SSH-окно можно оставить открытым.

До переноса данных логинов в новой базе нет. Если данные с Mac переносить
не нужно, на сервере выполните `voice-manage createsuperuser`. Если перенос
планируется, сначала перенесите базу: импорт требует пустой базы.

## Перенос рабочей базы с Mac

Выберите один Mac с актуальной рабочей базой. Остановите локальное
приложение через Ctrl+C; не запускайте его после переноса параллельно с сервером.
На других компьютерах также остановите копии с теми же кабинетами.
На выбранном Mac, в папке приложения:

```bash
.venv/bin/python manage.py backup_db
git pull --ff-only
bash start.sh --setup-only --no-input
.venv/bin/python manage.py export_transfer --output .local/voice-transfer.json
scp -i "$HOME/.ssh/voice_beget" .local/voice-transfer.json root@SERVER_IP:/root/voice-transfer.json
```

`--setup-only` обновляет схему и зависимости и не запускает сервер/очереди.
Экспорт сохраняет пользователей и хеши паролей, группы и роли, компании,
товары, исходные JSON, сообщения, AI-анализ, аудит, очередь ответов,
позиции синхронизации и паузы API. Активные браузерные сессии не переносятся:
понадобится повторный вход прежним логином и паролем. Сами ключи API находятся
в окружении, их задают отдельно на сервере.

Файл содержит рабочие данные и хеши паролей: права 0600, передача только по
SSH, хранение вне Git. Если файл экспорта уже существует, команда остановится;
для нового экспорта укажите другое имя, прежний файл не перезаписывается.

На сервере:

```bash
systemctl stop voice-web voice-worker voice-poll
install -o voice -g voice-app -m 0600 /root/voice-transfer.json /var/lib/voice/voice-transfer.json
voice-manage import_transfer /var/lib/voice/voice-transfer.json
voice-manage check
systemctl start voice-web
```

Импорт разрешён только в пустую рабочую базу: существующие данные не
перезаписываются. PostgreSQL-последовательности восстанавливаются вместе с
данными. После проверки переноса удалите временные файлы экспорта с сервера,
сохранив резервную копию на Mac в защищённом месте.

Проверьте вход, количество обращений, товары, кабинеты и очередь исходящих.
У уже отправленных/подтверждённых ответов сохраняются статусы, они не должны
публиковаться повторно. Queued остаются запланированными к отправке: проверьте
их актуальность перед включением worker. Sending/неопределённые результаты
требуют обычной сверки в приложении, повторная отправка вслепую не выполняется.

## Ключи и фоновые процессы

На сервере введите ключи скрытым вводом:

```bash
voice-set-key VOC_WB_TOKEN
voice-set-key VOC_YM_TOKEN
voice-set-key VOC_AI_KEY
```

Запускайте только команды для нужных интеграций. Имя переменной должно
совпадать с именем в карточке кабинета/компании. Значения не попадают в историю
команд и не выводятся на экран. Ключи из Mac не передаются автоматически.

Когда перенос проверен и все локальные копии остановлены:

```bash
systemctl restart voice-web
systemctl enable --now voice-worker voice-poll
```

Должен работать один poller и один worker. Лимиты WB, недельный период
синхронизации и проверки публикации сохраняются.
Учитывайте официальную доступность выбранного AI-провайдера в регионе сервера.

## Домен и HTTPS перед подключением сотрудников

1. Создайте A-запись поддомена на публичный IP сервера. AAAA добавляйте только
   при настроенном и доступном IPv6. Основной сайт остаётся на своём сервере.
2. Настройте отдельный Nginx server block для этого поддомена с проксированием
   на `http://127.0.0.1:8000`. Прокси должен **перезаписывать** `Host`,
   `X-Forwarded-Proto` и `X-Forwarded-For`; прямой публичный доступ к Gunicorn
   не открывайте. Для импорта задайте `client_max_body_size 6m` и
   `proxy_read_timeout 180s`. Перед перезагрузкой проверьте `nginx -t`.
3. Выпустите сертификат через `certbot --nginx -d YOUR_DOMAIN` и включите
   перенаправление HTTP на HTTPS. Проверьте `certbot renew --dry-run`.
4. В `/etc/voice/voice.env` добавьте домен в `DJANGO_ALLOWED_HOSTS`,
   задайте `DJANGO_CSRF_TRUSTED_ORIGINS=https://YOUR_DOMAIN`, `VOC_HTTPS=1`.
   Перезапустите три службы. HTTPS-настройка включает защищённые cookies,
   редирект и HSTS для этого хоста; HSTS preload и охват поддоменов не включаются.
5. Настройте сетевой доступ: публично 80/443, SSH по принятой схеме доступа.
   PostgreSQL/8000 не публикуются. При настройке firewall сначала сохраните
   SSH-доступ и проверьте второе подключение.
6. Создайте отдельные учётные записи сотрудникам, назначьте компании и роли.

Для первой установки без домена этот раздел выполняется позже, отдельно.
Не переключайте `VOC_HTTPS=1` при обычной проверке через HTTP SSH-туннеля:
браузер будет перенаправлен на HTTPS, которого в туннеле пока нет.

## Обслуживание

```bash
systemctl status voice-web voice-worker voice-poll --no-pager
journalctl -u voice-web -n 40 --no-pager
journalctl -u voice-poll -n 40 --no-pager
voice-manage backup_db
systemctl list-timers voice-backup.timer
```

PostgreSQL-копии имеют формат `pg_dump --format=custom`, расширение `.dump`
и права 0600. Восстановление через `pg_restore` выполняется в отдельную пустую
базу с последующей проверкой; существующую рабочую базу автоматически не стираем.
Версия `pg_dump` должна соответствовать серверу или быть новее него.
SQLite на Mac по-прежнему копируется SQLite Backup API.

Таймер запускается ежедневно около 03:30 UTC. Копии находятся на том же сервере:
до постоянной работы сотрудников настройте копирование в отдельное хранилище,
срок хранения и контроль свободного места. Автоматического удаления старых копий
в этой версии нет. Файл `/etc/voice/voice.env` резервируется отдельно с сохранением
прав доступа; он нужен для восстановления настроек и ключей.

Обновление существующей установки:

```bash
systemctl stop voice-web voice-worker voice-poll
voice-manage backup_db
cd /opt/voice
git pull --ff-only
bash deploy/install.sh
```

После проверки включите polling/worker, если они использовались до обновления.
При ошибке миграции установщик остановится; не запускайте повторную установку
поверх активных служб. Сохраните вывод ошибки без секретов для разбора.
