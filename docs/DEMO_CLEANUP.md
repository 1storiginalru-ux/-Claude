# Удаление стандартных демо-данных

Команда удаляет примеры `seed_demo`, чтобы они не попадали в Inbox, каталог,
показатели и расследования. Она не обращается к API маркетплейсов.

## Состав и границы

Обычный набор: 10 отзывов, 2 вопроса, 12 сообщений, 3 товара, 2 кабинета,
6 сопоставлений, 12 строк искусственных продаж и 24 порога. Также удаляются
их разметка, ручные решения, безопасные демо-черновики и чисто демонстрационные
расследования. Количество расследований может отличаться между версиями.

Выбираются только компании `is_demo=True`. Дополнительно проверяются стандартные
ProductID, метки обращений `demo-N` и их типы, значения искусственных продаж,
отсутствие исходных данных маркетплейса и пересечений с рабочими данными.
Идентификаторы продуктов и примеров вынесены в общий файл `desk/demo_data.py`,
который используется и созданием примеров, и очисткой.

Если есть незнакомые записи, работающий кабинет, отдельные продажи API, смешанное
расследование, рабочая привязка, общий с реальной компанией ProductID, отправка
Sending/Sent/Confirmed, внешний ID ответа/задачи или активная блокировка демо-опроса,
операция отменяется целиком. Обхода защит через `--force` нет.

Пользователи, Membership, команды, рабочие компании/кабинеты, API-ключи, глобальные
лимиты API, рабочие курсоры и паузы не изменяются. Аудит сохраняется; успешное
удаление регистрируется как `demo.purge`. Пустая демо-компания остаётся для аудита
и предотвращает повторный автоматический `seed_demo` при локальном старте.
В Inbox больше не показывается уведомление о демонстрационных обращениях.
Ручной явный вызов `seed_demo` по-прежнему может создать примеры заново.

## Обновление и очистка на сервере

В Терминале сервера от root, по одной команде. При ошибке остановиться:

```bash
systemctl stop voice-web voice-worker voice-poll
voice-manage backup_db
cd /opt/voice
git pull --ff-only
bash deploy/install.sh --purge-demo
systemctl enable --now voice-worker voice-poll
systemctl is-active voice-web voice-worker voice-poll
```

`--purge-demo` явно включает очистку в установщике после миграций и до запуска
веб-службы. Обычный `bash deploy/install.sh` сохраняет демо. Это обновление также
включает ручные решения, контроль товаров и исправление ложного скрытого негатива.

После успешного завершения видны счётчики удалённых записей, проверка HTTP/базы
и три строки `active`. Обновите страницу Voice в браузере.

## Отдельный предварительный просмотр

После обновления кода и миграций можно проверить состав без удаления:

```bash
voice-manage purge_demo
```

Отдельное удаление, если службы остановлены и копия уже создана:

```bash
voice-manage purge_demo --apply
```

Повторный запуск показывает нули и не создаёт новый аудит пустого удаления.
В локальной установке вместо `voice-manage` используется `.venv/bin/python manage.py`.
